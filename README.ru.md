# Fingerprint

Проверка приватности для обычных пользователей: страница показывает, что любой сайт узнаёт о вашем браузере в момент открытия, насколько уникальным это вас делает и как стать менее заметным для слежки.

**Сайт:** https://fprint.morgunov.tech · **Лицензия:** [MIT](LICENSE) · [English version](README.md)

## Что умеет

- **Что сайт видит сразу.** Браузер и ОС, экран и мониторы, GPU, ядра процессора и память, языки и часовой пояс, шрифты, хэши Canvas и аудио, хранилище, разрешения, батарея, медиаустройства. Без единого запроса разрешения. Раздел профиля превращает это в понятные догадки: модель устройства, вероятный регион, вероятность VPN, утечка IP через WebRTC.
- **Оценка уникальности.** Каждый сигнал взвешен по тому, насколько он распространён (частотные таблицы на основе EFF Panopticlick и исследований FingerprintJS, коррелирующие сигналы считаются один раз), а результат сравнивается с 25 000 смоделированных браузеров.
- **Советы по защите.** Рекомендации под то, что нашлось: часовой пояс не совпадает с IP, утечка WebRTC, открытый Canvas-отпечаток, — с шагами для Chrome, Firefox, Brave и Safari.
- **Симуляция трекеров.** Пять проверок. Три из них — приманки для блокировщика рекламы: страница вставляет три скрытых `<div>` с классами, которые блокировщики прячут (`ad_banner adsbygoogle`, `adsbox` с id `google_ads_frame`, `ad-placement sponsored-banner`), и через полсекунды проверяет, виден ли ещё каждый из них; в интерфейсе они подписаны «рекламный пиксель», «скрипт аналитики» и «рекламный фрейм», но никакой пиксель, скрипт или фрейм ниоткуда не загружается. Остальные две читают ваши настройки Do Not Track и Global Privacy Control.
- **Взгляд со стороны сервера.** Нажмите «Проверить сеть» — Worker покажет, что сервер видит до запуска JavaScript (IP, провайдер и ASN, версия TLS, протокол HTTP, порядок заголовков, Client Hints), а страница отметит, где это расходится с данными браузера. Также: тип подключения (домашнее, мобильное, дата-центр, VPN), проверка по 4 DNS-блоклистам (Barracuda, SpamCop, UCEPROTECT, PSBL), обратный DNS и тест скорости. `/api/scan` у Worker-а принимает и домен (DNS-записи, сертификаты из CT-логов, заголовки безопасности; поле WHOIS всегда пустое, см. «Приватность»); сама страница проверяет только ваш IP.
- **Story Mode.** Те же данные как рассказ: от открытия ноутбука до просмотра видео на YouTube — кто что видит на каждом шаге, почему это важно, что делать. Переключатель в шапке или `?mode=story`.
- Русский, английский и узбекский; светлая, тёмная и высококонтрастная темы; поделиться и распечатать.

## Приватность

- **Считается в вашем браузере:** все сигналы отпечатка, оценка уникальности, профиль и проверки трекеров. Страница их не отправляет, и ни одна третья сторона ваш отпечаток не видит. Единственный внешний скрипт — счётчик просмотров Cloudflare (ниже), который добавляет Pages.
- **Worker** получает ваш IP и заголовки запроса, как любой сервер. При открытии страница только читает у него агрегированную статистику. Счётчик лимита запросов на IP лежит в Workers KV и истекает через 60 секунд.
- **«Проверить сеть»** вызывает `/api/whoami` (ваш IP, его местоположение и ASN по данным Cloudflare, ваши заголовки; возвращаются вам, не сохраняются), тест скорости и `/api/scan` для вашего IP. Скан отправляет ваш IP в ipquery.io (запасной вариант — ipinfo.io) за местоположением, провайдером и типом подключения, в Google DNS (`dns.google`) за обратной записью и четырьмя проверками по блоклистам и в whoisjson.com. Последний вызов сегодня бесполезен: whoisjson.com требует API-ключ, у Worker-а его нет, и сервис отвечает ошибкой «нет API-ключа», которую Worker проглатывает, поэтому поле WHOIS всегда пустое; ваш IP при этом уходит туда при каждой проверке, пока провайдер не убран (запланировано отдельным изменением). Отчёт кэшируется в KV под вашим IP на один час. Только если Worker недоступен, браузер спрашивает публичные IP-сервисы напрямую: ipapi.co и freeipapi.com, затем ipify.org и myip.com, если и те не ответили.
- **Проверка домена** (`/api/scan?target=example.com`, только через API; страница такого не отправляет) дополнительно спрашивает Google DNS о записях домена, crt.sh о его сертификатах (логи certificate transparency) и отправляет один запрос `HEAD` самому домену по https, а при неудаче по http, чтобы прочитать его заголовки безопасности. Эти службы видят проверяемый домен, а ipquery.io и блоклисты — его адрес, не ваш.
- **Анонимная статистика:** каждый вызов `/api/whoami` прибавляет единицу к агрегированным счётчикам: всего проверок, браузер и мажорная версия, ОС, страна, версия TLS. Без IP, без идентификаторов, без времени. Страница использует их для строки «проверено отпечатков» в подвале и подсказок «X% посетителей» (после 100 проверок). Прочитать их может любой: `/api/stats`.
- **Cloudflare Web Analytics** считает просмотры без cookies.

## Как устроено

- `site/` — то, что раздаёт Cloudflare Pages. Без сборки, без фреймворка, без npm. `index.html` — всё приложение: разметка, стили и один встроенный скрипт со строками RU/EN/UZ, моделью уникальности и Story Mode. `src/profiler.js` — ES-модуль, который страница импортирует для профиля. Плюс `_headers`, `404.html`, `robots.txt`, `sitemap.xml` и `share-card.svg`.
- `worker/` — Cloudflare Worker `fingerprint-api` на чистом JavaScript, без зависимостей в рантайме: `/api/whoami`, `/api/check` (простой текст для `curl`), `/api/scan`, `/api/speedtest/*`, `/api/stats`, `/api/health`. В Workers KV лежат кэш сканов, статистика и лимит запросов (60 в минуту на IP).
- `selftest.js` запускает встроенный скрипт и `profiler.js` в песочнице Node `vm` с заглушкой DOM и проверяет хелперы, оценку, паритет ключей переводов и элементы управления. CI запускает его на каждом PR вместе с пробной сборкой Worker-а, `npm audit` и gitleaks.
- **Версии.** Выпуск называет одно число, и оно живёт в четырёх местах, которые должны совпадать: `APP_VERSION` в `site/index.html` (бейдж в подвале и окно истории изменений с теми же записями на RU/EN/UZ), `VERSION` в `worker/src/index.js` (его отдаёт `/api/health`), `version` в `worker/package.json` и верхняя запись [CHANGELOG.md](CHANGELOG.md). Выпуски помечаются тегами `vX.Y.Z` на `main`; с 2.2.0 версии следуют SemVer (раньше были из двух частей).

## Запуск локально

Wrangler требует Node.js 22 или новее.

```sh
# Сайт: раздаёт site/ на http://localhost:3000
npx wrangler pages dev --port 3000

# Worker: http://localhost:8787, KV эмулируется локально
cd worker && npm ci && npx wrangler dev

# Самопроверка: ничего устанавливать не нужно
node selftest.js
```

Страница обращается к задеплоенному Worker-у (`WORKER_API` в `site/index.html`). Порт 3000 есть в `ALLOWED_ORIGINS` Worker-а; на порту по умолчанию 8788 CORS эти вызовы заблокирует. Чтобы проверить локальный Worker, укажите в `WORKER_API` адрес `http://localhost:8787`.

## Деплой

- **Сайт:** Cloudflare Pages деплоит `main` и раздаёт `site/` (`pages_build_output_dir` в корневом `wrangler.toml`).
- **Worker:** деплоится вручную командой `cd worker && npm run deploy` (запускает `wrangler deploy`). В `worker/wrangler.toml` — привязка KV `CACHE` и `ALLOWED_ORIGINS`.

Для своей копии: создайте пространство KV (`npx wrangler kv namespace create CACHE`), впишите его id в `worker/wrangler.toml`, укажите в `ALLOWED_ORIGINS` свой сайт, а в `site/index.html` направьте `WORKER_API` на свой Worker. Секретов настраивать не нужно: ipquery.io, ipinfo.io, Google DNS и crt.sh используются без ключа. whoisjson.com ключ требует, а Worker его не отправляет, поэтому данные WHOIS всегда пустые (см. «Приватность»).
