# Fingerprint

Образовательная страница о приватности для людей без технической подготовки: шесть шагов от включения ноутбука до открытого сайта, и на каждом, на ваших реальных данных, кто и что о вас узнаёт и что с этим делать.

**Сайт:** https://fprint.morgunov.tech (по-английски: https://fprint.morgunov.tech/en/) · **API:** https://fprint.morgunov.tech/api/ · **Лицензия:** [MIT](LICENSE) · 🇬🇧 [In English](README.md)

## Что делает

Страница — один маршрут. Каждый шаг — карточка с одинаковыми частями: что измерено прямо сейчас (строки ваших реальных данных), кто это узнаёт (с именами из данных: Apple, Microsoft или Google для системы; Google, Apple, Mozilla, Brave и другие для браузера; ваш провайдер по названию; Cloudflare; владелец сайта), как это устроено, чем опасно и одно действие, под вашу систему и браузер.

1. **Вы открыли ноутбук** (или разблокировали телефон: формулировка следует за устройством). Модель, экран, видеокарта, память, ядра, батарея, часовой пояс, языки системы. Пока это ни у кого нет, но браузер отдаст это каждому сайту на шаге 6.
2. **Запустилась операционная система.** Система и версия, производитель, архитектура. Что производитель узнаёт при загрузке, объясняется, а не измеряется: из страницы этого не видно.
3. **Вы подключились к интернету.** Единственный шаг с кнопкой: «Узнать, что видит провайдер» отправляет один запрос к Worker-у сайта и объясняет, что уходит. После неё: ваш IP, название провайдера, где IP вас размещает, тип подключения, признаки VPN, часовой пояс по IP.
4. **Вы открыли браузер.** Название и версия (и доля посетителей с таким же), производитель, работает ли блокировщик рекламы, Do Not Track, Global Privacy Control, выданные разрешения, cookies.
5. **Вы ввели адрес сайта.** Что записывает DNS-сервер и что выдаёт соединение; после проверки — версия и шифр TLS, протокол HTTP, ближайший узел Cloudflare.
6. **Сайт открылся.** Что сервер получил до скриптов (User-Agent, языки, Client Hints, число заголовков), что собрали скрипты этой страницы (отпечатки Canvas, звука и WebGL, шрифты, утечка адреса через WebRTC, чужие ресурсы на этой странице) и проверка блокировщика приманками.

Потом **итог**: кто что узнал, чек-лист с одним действием на шаг, «Поделиться» (текст из ваших данных) и «Распечатать / Сохранить». Внизу «Все данные, которые отдал браузер» хранит сырые данные для любопытных, включая хеши отпечатков. Русский, английский и узбекский; светлая, тёмная и контрастная темы.

Через каждый шаг проходят три уровня честности: строки под «Измерено прямо сейчас» — реальные значения из вашего браузера; строки, которым нужен сервер, появляются после кнопки на шаге 3; то, чего из страницы не видно (телеметрия производителя ОС, журнал DNS), объясняется в «Как это устроено» и не выдаётся за измерение. Проверка блокировщика названа проверкой приманок: три скрытых элемента с классами, которые прячут блокировщики, плюс сигналы DNT и GPC; ничего ниоткуда не загружается.

## API

Worker, который стоит за кнопкой на шаге 3, открыт по адресу **https://fprint.morgunov.tech/api/** — на собственном адресе сайта: без ключа и регистрации, 60 запросов в минуту на IP. Его исходный адрес `https://fingerprint-api.xfxrrpkvr5.workers.dev` отвечает по тем же путям и продолжает работать.

```sh
# Что сервер видит о вас до запуска JavaScript, простым текстом
curl https://fprint.morgunov.tech/api/check

# То же в JSON
curl -H 'Accept: application/json' https://fprint.morgunov.tech/api/check

# Отчёт по IP или домену (для домена ещё сертификаты и заголовки безопасности)
curl 'https://fprint.morgunov.tech/api/scan?target=example.com'

# Анонимная агрегированная статистика; версия на проде
curl https://fprint.morgunov.tech/api/stats
curl https://fprint.morgunov.tech/api/health
```

`/api/whoami` — то, что вызывает страница: тот же JSON, что и `/api/check`, и каждый вызов добавляет единицу в анонимную статистику. `/api/speedtest/ping`, `/api/speedtest/download?size=N` (от 100 КБ до 25 МБ) и `POST /api/speedtest/upload` остаются для пользователей API; страница тест скорости больше не запускает.

## Приватность

- **Считается в вашем браузере:** каждая строка маршрута, догадки об устройстве и ОС, проверка приманок и проба WebRTC (она собирает ICE host-кандидаты без STUN-сервера, поэтому ничего не отправляет). Страница их не загружает, и ни одна сторонняя служба их не видит. Единственный внешний скрипт — счётчик просмотров Cloudflare (ниже), который добавляет Pages.
- **Worker** отвечает по адресу https://fprint.morgunov.tech/api/ — на том же хосте, что и страница, — и получает ваш IP и заголовки запроса, как любой сервер. При открытии страница только читает у него общую статистику. Счётчик лимита запросов на IP живёт в Workers KV и истекает через 60 секунд.
- **Кнопка на шаге 3** вызывает `/api/whoami` (ваш IP, определённые Cloudflare местоположение и ASN, ваши заголовки; возвращаются вам, не хранятся) и `/api/scan` для вашего IP. Скан отправляет ваш IP в ipquery.io (запасной — ipinfo.io) за местоположением, провайдером и типом подключения и в Google DNS (`dns.google`) за обратной записью и четырьмя проверками по чёрным спискам. Отчёт кэшируется в KV под вашим IP на час. Только если Worker недоступен, браузер спрашивает публичные сервисы IP напрямую: ipapi.co и freeipapi.com, затем ipify.org и myip.com, если и те не ответили.
- **Скан домена** (`/api/scan?target=example.com`, только API; страница домены не отправляет) ещё спрашивает у Google DNS записи домена, у crt.sh его сертификаты (журналы прозрачности сертификатов) и отправляет запрос `HEAD` самому домену по https, затем по http, следуя редиректам, чтобы прочитать заголовки безопасности: домен с редиректом получает больше одного запроса, а заголовки читаются с конечного адреса. Эти службы видят сканируемый домен, а ipquery.io и чёрные списки — его адрес, не ваш. WHOIS не запрашивается; поле `whois` остаётся `null` для совместимости.
- **Анонимная статистика:** каждый вызов `/api/whoami` добавляет единицу в агрегированные счётчики: всего проверок, браузер и мажорная версия, ОС, страна, версия TLS. Ни IP, ни идентификаторов, ни времени. Страница использует их для подписи «Проверено N раз» в подвале и пометки «у N% посетителей» в строке браузера (после 100 проверок). Прочитать их может любой по `/api/stats`. Счётчики — чтение-изменение-запись одного ключа KV, поэтому одновременные визиты могут потерять инкремент: это украшение, а не аналитика.
- **Cloudflare Web Analytics** считает просмотры без cookie.
- **Стили и шрифты** (дизайн-система morgunov.tech, IBM Plex) загружаются с https://s.morgunov.tech/ds/v1/ — сайта автора: как любой сервер, он видит ваш IP и браузер, cookie не ставит и аналитику не ведёт, и об отпечатке эти запросы ничего не несут. Если этот хост недоступен, страница работает на системном шрифте.

## Как устроено

- `site/` — то, что раздаёт Cloudflare Pages. Без сборки, без фреймворка, без npm: браузер загружает ES-модули как есть. `index.html` — разметка (вступление по-русски, читаемое без JavaScript, и блок JSON-LD), `assets/app.css` — стили на токенах дизайн-системы morgunov.tech (`https://s.morgunov.tech/ds/v1/`: `fonts`, `tokens` и `base` подключены в `<head>` по адресам с хешем содержимого; руководство — `ds/v1/USAGE.md` в [about-me-page](https://github.com/morgunovtech/about-me-page); раскладка и элементы управления свои, прямые углы, без теней, не жирнее 600, без эмодзи в оформлении), `src/` — код:
  - `app.js` — запуск, переключатели языка и темы, порядок отрисовки, кнопка на шаге 3, окно истории изменений; `config.js` (адреса, `APP_VERSION`), `state.js` (что страница уже знает), `dom.js` (хелперы).
  - `theme-init.js` — обычный скрипт в `<head>`, не модуль: тема до первой отрисовки (`data-theme` на `<html>`, атрибут, по которому переключаются токены; `auto` следует за системной настройкой) из `theme-preference` — ключа, общего для всех страниц morgunov.tech, так что тема, выбранная здесь, действует и на s.morgunov.tech, и наоборот.
  - `walk.js` — шесть шагов, итог и раздел сырых данных, собранные из снимка и состояния.
  - `i18n/ru.js`, `en.js`, `uz.js` — все строки страницы, одинаковые ключи в каждом файле; `changelog.js` — записи окна истории изменений.
  - `signals.js` — сигналы, которые браузер выдаёт сам, собираются один раз за просмотр (Canvas, один аудио-рендер, один WebGL-контекст, шрифты, разрешения, …), снимок и его хеш.
  - `device.js` — догадки об устройстве, ОС и браузере по User-Agent, Client Hints и железу и компании, которые за ними стоят.
  - `network.js` — всё, что уходит из браузера: Worker (`/api/whoami`, `/api/scan`, `/api/stats`), публичные IP-сервисы только когда Worker недоступен, эвристики VPN и проба WebRTC.
  - `trackers.js` (проверка приманок и проверка согласованности данных браузера), `share.js` (поделиться и сохранить).
  Плюс `_headers`, `404.html`, `robots.txt`, `sitemap.xml`, `llms.txt` и карточки для превью ссылок.
- **`/en/` и превью ссылок.** LinkedIn, Telegram и другие превью ссылок читают теги `og:`, не запуская страницу, поэтому английской странице нужны английские теги в самом HTML. `functions/en/index.js` — функция Pages: на `/en/` она отдаёт `site/index.html`, переписав теги `<head>` по-английски (`html lang`, описание, канонический адрес, `og:title`, `og:url`, картинку, `og:locale` и их двойники `twitter:`). Элемент `<title>` она тоже переписывает (с 3.1.2) — той строкой, которую скрипт страницы выставляет для английского после загрузки, поэтому поисковики и читатели без JavaScript видят на `/en/` английский заголовок. Язык страница берёт из адреса. Карточки — PNG 1200×630, потому что SVG LinkedIn и большинство мессенджеров не показывают: `share-card.png` для `/`, `share-card-en.png` для `/en/`. Их исходники — `share-card.svg` и `share-card-en.svg`; после правки перерисуйте карточку из корня репозитория в headless Chrome:

  ```sh
  for card in share-card share-card-en; do
    "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new \
      --user-data-dir="$(mktemp -d)" --hide-scrollbars --force-device-scale-factor=1 \
      --window-size=1200,630 --screenshot="$PWD/site/$card.png" "file://$PWD/site/$card.svg"
  done
  ```
- **Для поисковиков и ИИ-ассистентов:** в `<head>` `index.html` — мета подтверждения Яндекс Вебмастера и блок JSON-LD `WebApplication` (данные, которые браузер не выполняет; автор — тот же `Person`, что на s.morgunov.tech); каждая группа в `robots.txt` даёт Content Signals `search=yes, ai-input=yes, ai-train=yes` ([contentsignals.org](https://contentsignals.org)), потому что краулер со своей группой игнорирует `*`; `llms.txt` описывает страницу, её приватность и API простым текстом.
- `worker/` — Cloudflare Worker `fingerprint-api` на чистом JavaScript, без зависимостей в рантайме: `src/index.js` — маршрутизатор (`/api/scan`, `/api/speedtest/*`, `/api/stats`, `/api/health`), `src/whoami.js` собирает `/api/whoami` и `/api/check` (простой текст для `curl`) из запроса, `src/collector.js` запускает `providers/` для скана. В Workers KV лежат кэш сканов (час), статистика и лимит запросов (60 в минуту на IP).
- `selftest.js` импортирует модули страницы в Node с заглушками DOM и браузерных API и проверяет хелперы, строки (одинаковые ключи в трёх языках, каждый ключ, который читают модули, существует), маршрут (шесть шагов с реальными значениями, названные стороны, элементы управления, языки), проверку по кнопке на шаге 3 целиком (шаги 3, 5 и 6, итог, текст для «Поделиться», сырые данные), `whoami`, провайдеры и скан Worker-а, а также статические файлы: JSON-LD разбирается и называет канонический адрес, в каждой группе `robots.txt` есть сигналы, `llms.txt` ссылается на сайт, репозиторий и автора, обе карточки превью — PNG 1200×630, а функция `/en/` находит каждый тег, который переписывает, не оставляет русского в английских тегах превью и берёт те же английские тексты, что и страница. CI запускает его на каждом PR вместе с пробной сборкой Worker-а, `npm audit` и gitleaks.
- **Версии.** Выпуск называет одно число, и оно живёт в пяти местах, которые должны совпадать: `APP_VERSION` в `site/src/config.js` (бейдж в подвале; записи окна истории изменений — в `site/src/changelog.js`, те же, что здесь, на RU/EN/UZ), `VERSION` в `worker/src/index.js` (его отдаёт `/api/health`), `version` в `worker/package.json`, верхняя запись [CHANGELOG.md](CHANGELOG.md) и `?v=` в адресе каждого скрипта и стиля в `index.html` и `404.html` и в каждом `import` между модулями — так выпуск атомарен для браузера, закэшировавшего предыдущий (`site/_headers` к тому же заставляет `/src/*` и `/assets/*` перепроверяться при каждом открытии, как и страницу). `selftest.js` падает, если хоть одно из мест расходится. Поднять адреса: `sed -i -E "s/\?v=[0-9.]+/?v=X.Y.Z/g" site/index.html site/404.html site/src/*.js site/src/i18n/*.js`. Выпуски помечаются тегами `vX.Y.Z` на `main`; с 2.2.0 версии следуют SemVer (раньше были из двух частей).

## Запуск локально

Wrangler требует Node.js 22 или новее.

```sh
# Сайт: раздаёт site/ на http://localhost:3000
npx wrangler pages dev --port 3000

# Worker: http://localhost:8787, KV эмулируется локально
cd worker && npm ci && npx wrangler dev

# Self-test: установка не нужна
node selftest.js
```

Страница обращается к задеплоенному Worker-у по адресу https://fprint.morgunov.tech (`WORKER_API` в `site/src/config.js`). С `localhost` это запрос на другой origin: порт 3000 есть в `ALLOWED_ORIGINS` Worker-а; на порту по умолчанию 8788 CORS такие запросы блокирует. Чтобы попробовать свой локальный Worker, направьте `WORKER_API` на `http://localhost:8787`.

## Деплой

- **Сайт:** Cloudflare Pages деплоит `main` и раздаёт `site/` (`pages_build_output_dir` в корневом `wrangler.toml`), плюс функцию из `functions/` для `/en/`.
- **Worker:** деплоится вручную: `cd worker && npm run deploy` (запускает `wrangler deploy`). В `worker/wrangler.toml` — привязка KV `CACHE`, `ALLOWED_ORIGINS` и два хоста, на которых отвечает Worker: его адрес на workers.dev и маршрут `fprint.morgunov.tech/api/*`, который отправляет `/api/` на собственном хосте сайта в Worker вместо Pages.

Для своей копии: создайте пространство KV (`npx wrangler kv namespace create CACHE`), впишите его id в `worker/wrangler.toml`, укажите в `ALLOWED_ORIGINS` свой сайт, замените маршрут на свой в своей зоне или удалите его (тогда Worker отвечает только на workers.dev) и в `site/src/config.js` направьте `WORKER_API` на свой Worker. Секретов настраивать не нужно: ipquery.io, ipinfo.io, Google DNS и crt.sh работают без ключа.

## Что проект создаёт снаружи

- Проект Cloudflare Pages `fingerprint` (корневой `wrangler.toml`), который отдаёт `main` на своём домене fprint.morgunov.tech; его DNS-запись — в зоне morgunov.tech. https://fingerprint-66l.pages.dev — технический адрес проекта в Cloudflare: он продолжает работать, а `site/_headers` просит поисковики его не индексировать. Функция из `functions/en/` деплоится вместе с проектом. Снести: удалить проект и DNS-запись в панели Cloudflare.
- Worker Cloudflare `fingerprint-api` (`worker/wrangler.toml`) на маршруте `fprint.morgunov.tech/api/*` и на https://fingerprint-api.xfxrrpkvr5.workers.dev, с пространством KV, привязанным как `CACHE` (его id — в `worker/wrangler.toml`). Снести: `cd worker && npx wrangler delete` удаляет Worker вместе с маршрутом; затем удалить пространство KV (`npx wrangler kv namespace delete --namespace-id <id>` или панель).
- Сайт Cloudflare Web Analytics для страницы: маячок вставляет Pages, в репозитории на него ничего не ссылается. Убирается в панели Cloudflare.
- Поисковые консоли: Яндекс Вебмастер (мета `yandex-verification` в `site/index.html`) и Google Search Console (ресурс с префиксом адреса, подтверждён через доменный ресурс morgunov.tech; тега в репозитории нет). Удаляются там же.
- На GitHub: защита ветки `main` с обязательными проверками `selftest · worker` и `secrets`, «Allow auto-merge» для workflow Dependabot, сам Dependabot.
- Ключей API нигде нет: ipquery.io, ipinfo.io, Google DNS и crt.sh работают без ключа.
