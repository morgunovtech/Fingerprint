# Fingerprint

Проверка приватности для обычных пользователей: страница показывает, что любой сайт узнаёт о вашем браузере в момент открытия, насколько уникальным это вас делает и как стать менее заметным для слежки.

**Сайт:** https://fprint.morgunov.tech (по-английски: https://fprint.morgunov.tech/en/) · **API:** https://fprint.morgunov.tech/api/ · **Лицензия:** [MIT](LICENSE) · [English version](README.md)

## Что умеет

- **Что сайт видит сразу.** Браузер и ОС, экран и мониторы, GPU, ядра процессора и память, языки и часовой пояс, шрифты, хэши Canvas и аудио, хранилище, разрешения, батарея, медиаустройства. Без единого запроса разрешения. Раздел профиля превращает это в понятные догадки: модель устройства, вероятный регион, вероятность VPN, утечка IP через WebRTC.
- **Оценка уникальности.** Каждый сигнал взвешен по тому, насколько он распространён (частотные таблицы на основе EFF Panopticlick и исследований FingerprintJS, коррелирующие сигналы считаются один раз), а результат сравнивается с 25 000 смоделированных браузеров.
- **Советы по защите.** Рекомендации под то, что нашлось: часовой пояс не совпадает с IP, утечка WebRTC, открытый Canvas-отпечаток, — с шагами для Chrome, Firefox, Brave и Safari.
- **Симуляция трекеров.** Пять проверок. Три из них — приманки для блокировщика рекламы: страница вставляет три скрытых `<div>` с классами, которые блокировщики прячут (`ad_banner adsbygoogle`, `adsbox` с id `google_ads_frame`, `ad-placement sponsored-banner`), и через полсекунды проверяет, виден ли ещё каждый из них; в интерфейсе они подписаны «рекламный пиксель», «скрипт аналитики» и «рекламный фрейм», но никакой пиксель, скрипт или фрейм ниоткуда не загружается. Остальные две читают ваши настройки Do Not Track и Global Privacy Control.
- **Взгляд со стороны сервера.** Нажмите «Проверить сеть» — Worker покажет, что сервер видит до запуска JavaScript (IP, провайдер и ASN, версия TLS, протокол HTTP, порядок заголовков, Client Hints), а страница отметит, где это расходится с данными браузера. Также: тип подключения (домашнее, мобильное, дата-центр, VPN), проверка по 4 DNS-блоклистам (Barracuda, SpamCop, UCEPROTECT, PSBL), обратный DNS и тест скорости. `/api/scan` у Worker-а принимает и домен (DNS-записи, сертификаты из CT-логов, заголовки безопасности; запроса WHOIS нет, поле `whois` для совместимости всегда `null`); сама страница проверяет только ваш IP.
- **Story Mode.** Те же данные как рассказ: от открытия ноутбука до просмотра видео на YouTube — кто что видит на каждом шаге, почему это важно, что делать. Переключатель в шапке или `?mode=story`.
- Русский, английский и узбекский; светлая, тёмная и высококонтрастная темы; поделиться и распечатать.

## API

Worker, который стоит за «Проверить сеть», открыт по адресу **https://fprint.morgunov.tech/api/** — на собственном адресе сайта: без ключа и регистрации, 60 запросов в минуту на IP. Его прежний адрес, `https://fingerprint-api.xfxrrpkvr5.workers.dev`, отвечает на те же пути и продолжает работать.

```sh
# Что сервер видит о вас до запуска JavaScript, простым текстом
curl https://fprint.morgunov.tech/api/check

# То же в JSON
curl -H 'Accept: application/json' https://fprint.morgunov.tech/api/check

# Отчёт по IP или домену (для домена — ещё сертификаты и заголовки безопасности)
curl 'https://fprint.morgunov.tech/api/scan?target=example.com'

# Анонимная агрегированная статистика; задеплоенная версия
curl https://fprint.morgunov.tech/api/stats
curl https://fprint.morgunov.tech/api/health
```

`/api/whoami` вызывает сама страница: тот же JSON, что у `/api/check`, и каждый вызов прибавляет единицу к анонимной статистике. Тест скорости использует `/api/speedtest/ping`, `/api/speedtest/download?size=N` (от 100 КБ до 25 МБ) и `POST /api/speedtest/upload`.

## Приватность

- **Считается в вашем браузере:** все сигналы отпечатка, оценка уникальности, догадки об устройстве и ОС, проверки трекеров и проба WebRTC (она собирает ICE host-кандидаты без STUN-сервера, поэтому ничего не отправляет). Страница их не отправляет, и ни одна третья сторона ваш отпечаток не видит. Единственный внешний скрипт — счётчик просмотров Cloudflare (ниже), который добавляет Pages.
- **Worker** отвечает по адресу https://fprint.morgunov.tech/api/ — на том же хосте, что и страница, — и получает ваш IP и заголовки запроса, как любой сервер. До 2.3.0 страница обращалась к нему по адресу `fingerprint-api.xfxrrpkvr5.workers.dev`: переезд поменял имя хоста, с которым говорит браузер, но не то, что он отправляет, и старый адрес по-прежнему отвечает. При открытии страница только читает у него агрегированную статистику. Счётчик лимита запросов на IP лежит в Workers KV и истекает через 60 секунд.
- **«Проверить сеть»** вызывает `/api/whoami` (ваш IP, его местоположение и ASN по данным Cloudflare, ваши заголовки; возвращаются вам, не сохраняются), тест скорости и `/api/scan` для вашего IP. Скан отправляет ваш IP в ipquery.io (запасной вариант — ipinfo.io) за местоположением, провайдером и типом подключения, в Google DNS (`dns.google`) за обратной записью и четырьмя проверками по блоклистам. Запроса WHOIS нет. Отчёт кэшируется в KV под вашим IP на один час. Только если Worker недоступен, браузер спрашивает публичные IP-сервисы напрямую: ipapi.co и freeipapi.com, затем ipify.org и myip.com, если и те не ответили.
- **Проверка домена** (`/api/scan?target=example.com`, только через API; страница такого не отправляет) дополнительно спрашивает Google DNS о записях домена, crt.sh о его сертификатах (логи certificate transparency) и отправляет один запрос `HEAD` самому домену по https, а при неудаче по http, чтобы прочитать его заголовки безопасности. Эти службы видят проверяемый домен, а ipquery.io и блоклисты — его адрес, не ваш.
- **Анонимная статистика:** каждый вызов `/api/whoami` прибавляет единицу к агрегированным счётчикам: всего проверок, браузер и мажорная версия, ОС, страна, версия TLS. Без IP, без идентификаторов, без времени. Страница использует их для строки «проверено отпечатков» в подвале и подсказок «X% посетителей» (после 100 проверок). Прочитать их может любой: `/api/stats`.
- **Cloudflare Web Analytics** считает просмотры без cookies.

## Как устроено

- `site/` — то, что раздаёт Cloudflare Pages. Без сборки, без фреймворка, без npm: браузер загружает ES-модули как есть. `index.html` — разметка (и блок JSON-LD), `assets/app.css` — стили, `src/` — код:
  - `app.js` — запуск, элементы управления (язык, тема, «История», «Проверить сеть», «Поделиться», сохранение, окна истории изменений и методики) и порядок отрисовки; `config.js` (адреса, `APP_VERSION`), `state.js` (что страница уже знает), `dom.js` (хелперы).
  - `i18n/ru.js`, `en.js`, `uz.js` — все строки интерфейса, одинаковые ключи в каждом файле; `changelog.js` — записи окна истории изменений.
  - `signals.js` — сигналы, которые браузер выдаёт сам, собираются один раз за просмотр (Canvas, один аудио-рендер, один WebGL-контекст, шрифты, разрешения, …), снимок и его хеш.
  - `entropy.js` — модель уникальности: таблицы частот, информационное содержание комбинации и её процентиль среди 25 000 сэмплированных браузеров.
  - `device.js` — догадки об устройстве, ОС и браузере по User-Agent, Client Hints и железу.
  - `network.js` — всё, что уходит из браузера: Worker (`/api/whoami`, `/api/scan`, `/api/stats`, тест скорости), публичные IP-сервисы только когда Worker недоступен, эвристики VPN и проба WebRTC.
  - `trackers.js` (приманки для блокировщиков и проверка согласованности данных браузера), `report.js` (строки данных, карточки рисков, рекомендации, подробные карточки), `story.js` (режим «История»), `server-view.js` (строки сканирования, серверный отпечаток и сравнение сервер/браузер), `share.js` (поделиться и сохранить).
  Плюс `_headers`, `404.html`, `robots.txt`, `sitemap.xml`, `llms.txt` и карточки для превью ссылок.
- **`/en/` и превью ссылок.** LinkedIn, Telegram и другие превью ссылок читают теги `og:`, не запуская страницу, поэтому английской странице нужны английские теги в самом HTML. `functions/en/index.js` — функция Pages: на `/en/` она отдаёт `site/index.html`, переписав теги `<head>` по-английски (заголовок, описание, канонический адрес, `og:url`, картинку, `og:locale`); язык страница берёт из адреса. Карточки — PNG 1200×630, потому что SVG LinkedIn и большинство мессенджеров не показывают: `share-card.png` для `/`, `share-card-en.png` для `/en/`. Их исходники — `share-card.svg` и `share-card-en.svg`; после правки перерисуйте карточку из корня репозитория в headless Chrome:

  ```sh
  for card in share-card share-card-en; do
    "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new \
      --user-data-dir="$(mktemp -d)" --hide-scrollbars --force-device-scale-factor=1 \
      --window-size=1200,630 --screenshot="$PWD/site/$card.png" "file://$PWD/site/$card.svg"
  done
  ```
- **Для поисковиков и ИИ-ассистентов:** в `<head>` `index.html` — мета подтверждения Яндекс Вебмастера и блок JSON-LD `WebApplication` (данные, браузер их не выполняет; автор — тот же `Person`, что на s.morgunov.tech); в каждой группе `robots.txt` — Content Signals `search=yes, ai-input=yes, ai-train=yes` ([contentsignals.org](https://contentsignals.org): страницу можно показывать в поиске, использовать в ответах ИИ и для обучения ИИ), потому что робот со своей группой не читает `*`; `llms.txt` простым текстом описывает страницу, приватность и API.
- `worker/` — Cloudflare Worker `fingerprint-api` на чистом JavaScript, без зависимостей в рантайме: `src/index.js` — маршрутизатор (`/api/scan`, `/api/speedtest/*`, `/api/stats`, `/api/health`), `src/whoami.js` собирает `/api/whoami` и `/api/check` (простой текст для `curl`) из запроса, `src/collector.js` запускает `providers/` для скана. В Workers KV лежат кэш сканов (час), статистика и лимит запросов (60 в минуту на IP). Статистика — чтение-изменение-запись одного ключа KV, поэтому одновременные визиты могут потерять инкремент: это украшение, а не аналитика.
- `selftest.js` импортирует модули страницы в Node с заглушками DOM и браузерных API и проверяет хелперы, оценку, строки (одинаковые ключи в трёх языках, каждый ключ, который читают модули, существует), элементы управления, «Проверить сеть» целиком (IP, скорость, строки сканирования, серверный отпечаток, строка WebRTC), значения режима «История» и `whoami`, провайдеры и скан Worker-а, а также статические файлы: JSON-LD разбирается и называет канонический адрес, в каждой группе `robots.txt` есть сигналы, по одной строке, `llms.txt` ссылается на сайт, репозиторий и автора, обе карточки превью — PNG 1200×630, а функция `/en/` находит каждый тег, который переписывает, не оставляет русского в английских тегах превью и берёт те же английские тексты, что и страница. CI запускает его на каждом PR вместе с пробной сборкой Worker-а, `npm audit` и gitleaks.
- **Версии.** Выпуск называет одно число, и оно живёт в четырёх местах, которые должны совпадать: `APP_VERSION` в `site/src/config.js` (бейдж в подвале; записи окна истории изменений — в `site/src/changelog.js`, те же, что здесь, на RU/EN/UZ), `VERSION` в `worker/src/index.js` (его отдаёт `/api/health`), `version` в `worker/package.json` и верхняя запись [CHANGELOG.md](CHANGELOG.md). Выпуски помечаются тегами `vX.Y.Z` на `main`; с 2.2.0 версии следуют SemVer (раньше были из двух частей).

## Запуск локально

Wrangler требует Node.js 22 или новее.

```sh
# Сайт: раздаёт site/ на http://localhost:3000
npx wrangler pages dev --port 3000

# Worker: http://localhost:8787, KV эмулируется локально
cd worker && npm ci && npx wrangler dev

# Самопроверка: ничего устанавливать не нужно
node selftest.js
```

Страница обращается к задеплоенному Worker-у по адресу https://fprint.morgunov.tech (`WORKER_API` в `site/src/config.js`). С `localhost` это запрос на другой origin: порт 3000 есть в `ALLOWED_ORIGINS` Worker-а; на порту по умолчанию 8788 CORS эти вызовы заблокирует. Чтобы проверить локальный Worker, укажите в `WORKER_API` адрес `http://localhost:8787`.

## Деплой

- **Сайт:** Cloudflare Pages деплоит `main` и раздаёт `site/` (`pages_build_output_dir` в корневом `wrangler.toml`), а также функцию из `functions/` для `/en/`.
- **Worker:** деплоится вручную командой `cd worker && npm run deploy` (запускает `wrangler deploy`). В `worker/wrangler.toml` — привязка KV `CACHE`, `ALLOWED_ORIGINS` и два адреса, на которых отвечает Worker: его адрес на workers.dev и маршрут `fprint.morgunov.tech/api/*`, который отдаёт `/api/` на собственном адресе сайта Worker-у вместо Pages.

Для своей копии: создайте пространство KV (`npx wrangler kv namespace create CACHE`), впишите его id в `worker/wrangler.toml`, укажите в `ALLOWED_ORIGINS` свой сайт, замените маршрут своим в своей зоне или удалите его (тогда Worker отвечает только на workers.dev), а в `site/src/config.js` направьте `WORKER_API` на свой Worker. Секретов настраивать не нужно: ipquery.io, ipinfo.io, Google DNS и crt.sh используются без ключа.
